# Mayorly app: instructions for Claude

This is the application layer of Mayorly, a life OS: entries filed into ledgers, one desk timer, tomatoes that pay a coin each. Windows and macOS, Electron, React. The product rules come from `mayorly-design`; this repo turns them into code and puts a transparent HUD on top.

## Rules that are not negotiable

- **Every rule lives in `src/core`, and `src/core` stays pure.** No Electron, no DOM, no `Date.now()`, no `Math.random()`. Time, ids and randomness arrive through `Ctx`. If a rule needs the clock, pass it in.
- **State changes only through `reduce()`.** The main process is the only writer. Renderers dispatch actions and render snapshots. Do not add renderer-side state that matters after a restart.
- **The economy is the spec's.** One coin per tomato; a tomato grown on an entry is paid when that entry is cleared (the harvest), ledger time with no entry pays as it goes, a deleted entry forfeits its tomatoes. No bonus for long sittings, coins only from desk time; the couch costs what the desk pays, one coin for each whole tomato of time on a couch item, counted from its intervals like a task's tomatoes, so switching in and out neither saves nor costs anything (the founder's rule since 2026-11-22: nine hours of a game at 30 minutes a tomato is 18 coins); rests are free, nothing is earned on the couch. No streaks, no decay, no penalties, nothing that punishes a hold or a bad week. A ledger with `pays` off (paid work) is outside the economy: its tomatoes ripen and count, mint nothing and are never charged (`ledgerPays` in the reducer). Change `src/core/rules.ts` only after the design repo changes.
- **No AI-generated art.** Every sprite is the founder's, drawn by hand in mayorly-assets and shown as it is at a whole-number scale: never drawn, generated, scaled, recoloured or cropped into new files here. The app icon is his tomato at integer scale. Gaming mode shows `pet.tomato.gaming`, his tomato in a headset on a 24x24 canvas with the tomato in its middle. UI icons come from Phosphor unless the founder has drawn one (`lib/art.ts`: a drawn sprite wins, the Phosphor icon is its fallback); do not hand-draw SVG icons. A ledger's glyph is a Phosphor name from the catalogue in `lib/glyphs.tsx`; the clerk may *choose* a name from that list (`pickGlyph`), never draw one, and a `glyph.<name>` the founder drew shows in its place.
- **No em dashes in user-visible copy.** HUD copy is short, plain, and neutral. The clerk speaks in machine-log voice only.

## Checking your work

```
npm test             core rules
npm run typecheck    everything
npm run web          the HUD at localhost:5199 (?demo for sample data, ?fresh for first run, ?art for the art bench)
npm run art          copy the founder's drawings from ../mayorly-assets (-- --watch: on every save)
npm run ship:mac     build Mayorly.app, install it in /Applications, relaunch it
npm run dist:win     on Windows: build the installer and the portable exe into dist/
npm run phone        the phone app at localhost:5200 (?demo, ?fresh)
npm run ship:ios     build the iPhone app, install it on the paired phone, open it
scripts/e2e-drag.ps1 on Windows: the built app in a profile of its own, its tomato dragged and right-clicked with real mouse input
```

The drag of the tomato on Windows is checked end to end by CI (`.github/workflows/ci.yml`, job `drag`), which runs `scripts/e2e-drag.ps1` on a Windows runner: a second Mayorly with `MAYORLY_DATA_DIR` (its own save, pet place, log and single-instance lock), dragged with SendInput, after the pointer left, after a stall, and right-clicked for its menu. Run it there, not on the founder's computer, which it takes the mouse of; it closes every process it started.

There is no staging: the founder runs the installed app, so a change is done when the new app is up. On a Mac that is `ship:mac`. On Windows it is `npm run dist:win`, then quit the running Mayorly from the tray and run `dist\Mayorly-Setup-<version>.exe`, which replaces the installed copy and relaunches it. From a Claude desktop session, run the installer with `/S` and start the app with `explorer.exe "%LOCALAPPDATA%\Programs\Mayorly\Mayorly.exe"`, never directly: Claude is a packaged Windows app, so anything it starts directly gets a private copy of `%APPDATA%` (`%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming`), with a different save and sign-in from the Mayorly the founder opens. Those shells also read that private copy, so files there can hide the real ones. `npm run dev` is for iterating (hot reload, and on a Mac with `MAYORLY_DEBUG=1` the `SIGUSR1`/`SIGUSR2` previews, which Windows has no signals for); the dev instance and the installed app share one single-instance lock, so only one runs at a time and the ship script quits whichever is up.

Work through tickets one at a time. For each fix, check it, commit and push it, ship it (`ship:mac`, or `dist:win` and the installer), and verify the installed app is running before closing the ticket or starting the next one. The founder actively tests the installed app.

One codebase, two desktops. `main` is the branch both are built from; the Windows installer and the Mac disk image come out of the same tag (`.github/workflows/dist.yml`). Platform differences live behind `process.platform === 'darwin'` in the main process and `IS_MAC` in the renderer, nowhere else. The portable Windows exe never checks for updates and never registers `mayorly://`, since it unpacks to a fresh temp folder each run.

To screenshot the browser preview at full resolution:

```
SHOT_URL="http://localhost:5199/?demo" SHOT_OUT=shot.png SHOT_JS='...' npx electron scripts/shot.cjs
```

`?demo` and `?fresh` put `window.__mayorly = { dispatch, state }` on the page, so `SHOT_JS` (or the console) can drive the HUD: dispatch a harvest, open the deck with a synthetic keydown, and so on. Parameters go in the environment, which works the same on both platforms; Electron on Windows exits before running the script when a file path is passed as a positional argument. The capture window is offscreen with throttling off; a plain hidden window never runs `requestAnimationFrame`, so Motion animations would stay at their initial frame.

## Things that look like bugs and are not

- **The founder's sprites come from mayorly-assets by slot id, and a missing one is normal.** `npm run art` (`scripts/art.mjs`) copies each `art/<id>@1x.png` there that passes the art standard's own validator into `src/renderer/src/assets/art/<id>.png` (a blank scaffold or a broken file never comes across, so the app keeps its last good copy); the tomato also goes to `build/tomato@1x.png` and the icons are made again. `lib/art.ts` finds a sprite by id (`art(id)`, undefined until drawn; `ART` lists every id with its canvas), and `Pixel`, `PixelAnim` and `ArtIcon` (`lib/Pixel.tsx`) show it at a whole-number scale with `image-rendering: pixelated`, else the `fallback`: the plain tomato, a Phosphor icon, the CSS that was there. So a drawing can land any day and code never waits for it. The pet's states (`hud/PetSprite.tsx`: gaming, then carried, then the hop, then the desk's tone; a 24x24 canvas centred on the 48 px tomato at 3x, the plain sprite kept hidden underneath as the drag box) replace the breathing scale once drawn; the coin turns in flight by frames (`icon.coin.spin`), never by CSS rotate; `PixelNumber` draws the founder's numerals when `font.digits` exists. Nothing may tilt, rotate or scale a sprite by a fraction at rest: the deck is flat (it moves in depth only while opening), the Plus menu's arms sit on a flat `.plus-board` moved to where they showed on the leaning rig (`ARM_AT`, whole pixels; never put them back on the rig or centre them with a percentage translate), the phone's tomato hops in whole pixels without rotating, and sprites in the deck body cancel the deck's text zoom. The Shelf tab's picture (`deck/ShelfScene.tsx`, geometry in `shelfLayout.ts`, held by its test to the bookshelf slot's bays, the spine box measured from the PNGs) shows the ledgers as spines on his shelf, hand-written ones locked, the desk working while a block runs once drawn, and the mail tray while the tray holds entries; `deck/ui9.ts` makes his parchment (sliced at 9) and wood (at 8) into border-image frames. A drawn `glyph.<name>` (Phosphor name, `-` as `_`) replaces that Phosphor glyph everywhere `Glyph` shows it, in its own colours. Art is never tinted, recoloured or cropped into new files. The art bench (`/?art` in `npm run web`, dev only, never in a build, never writes storage) shows every id at 1x and at the app's scales, the pet's corner and the Shelf tab in place, and a magenta dashed box for each one not drawn; with `npm run art -- --watch` beside it, a save in Aseprite shows within a second without a reload (Vite's HMR re-runs `art.ts`; keep modules that import it exporting only components, or a save reloads the page). The HUD scale slider is not snapped, so a scale other than 100% resamples the pet; and the Plus menu's fit scale on the portrait monitor does the same.

- **Option+R skips only the current rest.** The configurable global `hotkeys.skipRest` dispatches `desk/skipRest`, which returns to the task saved behind the rest and starts it immediately, including when the rest is held or waiting. It keeps the sitting and swap history, and does nothing outside rest. A superset returns to the same slot rather than advancing; normal Skip still advances the plan.

- **Nothing cleared or deleted is gone.** A cleared entry stays in `entries` with `doneAt` and a `history` of every clear and reopen (`core/history.ts`, with the notes and checklist as they were at each clear). A deleted entry moves to `state.trash` with `deletedAt` (`entry/delete`), keeps its segments and so its tomatoes, and comes back with `entry/restore` (its ledger if it still exists, else the tray; `restoredAt` set). `trash/drop` and `trash/empty` are for good; anything older than `TRASH_KEEP_MS` (thirty days) is purged on the next delete or restore. In a merge the trash is a log where the later deletion wins, and a live entry restored after that deletion stays live (`restoredAt` also counts as a making, so a restore since the last sync is kept). `deck/EntryHistory.tsx` is the screen: cleared or the trash, j and k, Enter, u, x, t, /, Backspace.
- **The desk has one clock, so its intervals never overlap.** `closeSegment` ends every open interval and `openSegment` ends any stray first; `untangle` in `accounting.ts` runs on load and after every merge and ends each interval no later than the next one starts. From 2026-11-19 two copies of one block end came through a merge as two open rests, closing only the first open interval kept a stray open through every switch after it, and time was counted two to three times over (55.6 hours of focus recorded for 16.9 real). Coins already paid from that time stay paid; the unpaid caches come down to the real time.
- **Couch coins come from couch intervals.** `couchCharges` walks an item's leisure intervals in order, at each sitting's tomato length, and owes a coin for each whole tomato not yet paid, dated when it completed; `chargeCouch` in the reducer takes them as they come due (from `mint`, so on the tick and before any switch, park or stand down), and `settleCouch` takes them quietly on load and after a merge. A coin is `couch:<item>:<k>`, so two computers settling the same time make one record. Coins the old per-block rule took count as the first tomatoes. The couch runs only with a coin in hand: when the balance drops below one on the couch (its last coin, or a purchase), the tick ends the sitting with `Out of coins: back to the desk`. `taskTomatoes` shows a couch item's tomatoes by the same count, so the number beside the timer is what it has cost.
- **Task tomatoes come from task intervals.** `accounting.ts` sums each focus segment's end minus start, divided by its sitting's locked tomato length. Fractions survive switches and sittings. `Entry.tomatoes` is a derived cache of whole tomatoes not yet paid; the displayed count includes all work. Mint before switching, parking or clearing. Migration and merge rebuild caches from closed segments, preserve coin records, and never replay historical ledger payments. Entry-free time has a separate counter per ledger in each sitting.

- **Work and rest alarms are per machine.** `settings.alarms` is in `DEVICE_SETTINGS`; each choice has a built-in tone or a local custom asset id. `src/main/alarms.ts` copies uploads into `alarms/` beside the save. Audio bytes never enter state or sync. The renderer decodes a picked file before saving it, caches decoded audio for playback, and plays at most 15 seconds. Preview works with Sound cues off; automatic alarms obey it. The native picker uses `dialogOpen` so the deck stays open. The sound library (`deck/SoundSearch.tsx`, `lib/soundSearch.ts`) searches a catalogue that ships with the app as you type (`lib/sound-index.json`, about 1,900 short Freesound clips found through Openverse; `node scripts/sound-index.mjs` rebuilds it), and asks Openverse itself only after a pause when the catalogue has under 8 matches, or on Enter: that API takes seconds and allows anonymous callers about 20 calls a minute and 200 a day, so calls are cached per word and kept 3.5 seconds apart. The CSP's `connect-src` names exactly those two hosts, and a sound starts downloading when the pointer reaches its row. A chosen clip is downloaded as a data URL and saved through the same `alarms.save` as an upload, its name carrying the creator and licence.

- **The resting HUD is only the tomato and a number, on both desktops.** Hover gives one line of text and a hop, nothing more. The objectives strip, the centre callouts and the kill feed of the first HUD stay mounted but hidden, everywhere, because the callout plays the block alarms and the switch sound (`sfx.switch`, a synthesised weapon-swap thud through a compressor, `switchCue` in `lib/sfx.ts`): once per step that makes a `swap` or `switch` event, so Alt+Q, a pick, a parked session brought back and every automatic switch sound the same, but not a step that also clears (its ding) and not a fresh deploy (the work alarm). The Plus menu's browsing keeps the light `sfx.swap` clack. Those steps and the desk's other moments hit the screen too (below). A hotkey that failed to register speaks through the pet's caption, not a toast. Hold, skip, clear and stand down live in the Plus menu and the command line; there is no control strip.
- **Every moment on the desk hits the screen, each its own way.** `shared/impact.ts` (pure) reads one step's events and the desk before it (`deskSeen`) as one moment, the strongest when there are several: a task done (`cleared`), a switch (`switchedIn`), focus ending (a rest block), rest ending (a block after a rest; `Next` after another block), a start (a block from idle), a sitting ending, a pause or a resume (a change of `desk.status`, or the same block going again), a tomato. Each moment has its style in `settings.impact.styles` (a device setting; `ImpactStyle`: `ripple`, a tsunami of three crests rolling out from the tomato; `shockwave`, one heavy ring, a rim flash and a jolt; `edges`, the old glow, `hud/SwitchPulse.tsx`; `sweep`, a band crossing away from the tomato; `tide`, colour rising from the bottom and draining; `off`), its colour (the task's, `REST_COLOR`, `QUIET_COLOR`, `TOMATO_COLOR`) and words, said big in the middle of the tomato's screen with `impact.words` (`Switched to` and the task, `Done`, `Focus done` with `Rest, 5 min`...). Main decides (`impactFor` in `index.ts`, only on the computer running the desk, never in gaming mode or while a League match of yours runs, `ownLeagueMatchNow`) and `overlay.impact` plays it: the Windows overlay draws the tomato's screen itself, a Mac's effects window does (the pet's window is too small), and with `impact.everyScreen` an `EffectsWindow` on every other display does (kept warm while that is on). Every screen gets one `at` and `reach` (`reachOf`, the farthest corner of all of them from the tomato) with the tomato in its own pixels, and `hud/Impact.tsx` draws each frame on a canvas from `Date.now() - at`, so a wave leaving one monitor arrives on the next as on one big screen, and a window that showed late joins it where it has got to. A tsunami crashes into every edge but one another screen touches (`wallsOf`, from the displays' bounds; `walls` in the effect): spray where each crest meets the edge, running along it, and the crest bouncing back, drawn from the tomato's mirror image in that edge; the jolt lands with the first crash. Speed: Chromium paints the transparent overlay in software on Windows, so the canvas is drawn at half resolution (`RES`) and the words move only by transform and opacity (a blur or filter animation is repainted every frame; the 0.1.99 tsunami lagged); a run with slow frames logs `[impact] <style> slow` with its frame count, worst frame and canvas size. The words' title dances letter by letter (`hud/Wobble.tsx`, Balatro's text). Only Mayorly's layer moves; the person's windows are never moved and the screen is never captured. The browser build plays its own (`web.ts`). Settings, Sound and impact, has a style and Try for each moment (`bridge.previewImpact`, which plays on every screen it would), Every screen and the words. 0.1.97's `switchPulse` off became the switch's style off.
- **Tips teach the keys, and force mode makes you use them.** A control a key also does carries `tip(id, does?, key?)` (`lib/tips.ts`: a keymap id such as `deck.tab` with its own key for a range, or `hotkey:<action>`); `hud/Tips.tsx`, in App, listens to every pointer down in capture and, with `settings.tips.on` (a device setting), shows that key as bound now, big in the middle (`.tip-card`; `.tip` is the Record tab's chart tooltip). With `tips.force` the pointer down, mouse down and up and the click are swallowed before React hears them, so nothing happens until the key is pressed; a click from the keyboard (`detail` 0) always passes. Pressing the key (`pressesTip`, or for a global hotkey the command it sends) says Nice. Every tip shows the two global hotkeys under it, `tipsForce` (Ctrl+Alt+.) and `tips` (Ctrl+Alt+,), registered like the rest (`toggleTips` in `index.ts`, the pet says what changed; the web bridge handles them in the page); Settings, Hotkeys, has both toggles. Controls marked so far: the deck's tabs and close, the pet's sign (the swap menu), a Flow row's start, clear and delete, Blitz, Auto-classify, History, the Leisure switch, the calendar's weeks and Today, the Plus menu's items, Find's results, Settings' rail and Keymap button. Not in a Mac's pet-sized window, which has no middle. `tips.echo` echoes the keys pressed in a panel at the foot of the screen (`hud/KeyCast.tsx`), with a combo for keys within 900 ms of each other, growing and reddening, as Balatro's mult.
- **Everything answers, Balatro's way, and settles where it was.** `hud.css`, juice: a press squashes a button and the release springs back past its size (the `scale` property, so a control's own translate is kept); tabs jiggle under the pointer and pop when chosen; the row j and k move to snaps in; every keystroke in a box thumps the box (`.juice-type`, App's input listener); results pop in one after another (`--i`); the deck rises with a bounce and each tab's page slides in from the side you moved toward (the body is keyed by tab); Capture, Find and the switcher pop in with a twist. The coins (`hud/CashIn.tsx`): each landing jolts the counter by whole pixels on the `translate` property (apart from Motion's transform), flashes it, hops its number (the founder's digits only hop, text may swell), throws sparks and a chip, and the last slams the whole amount in, letters dancing; spending in red. Every one of these ends at scale 1, no turn and no offset, so no sprite rests resampled, and only small things move, so the overlay stays cheap. The shelf's bays are left out (spines). Reduced motion turns them off.
- **The overlay window is never focusable in field mode.** That is how it avoids stealing keystrokes. Plus, deck and capture flip it on and hand focus back with `blur()`.
- **A held Alt+T fires the command repeatedly.** The renderer ignores repeats until the key is released; releasing after 400 ms closes the menu (hold to peek), unless an arm was steered meanwhile, which commits the open.
- **The Plus menu's keys are the keymap's `plus` scope**, matched by position with Option ignored (`actionFor(e, 'plus', settings, { ignoreShift: true, ignoreAlt: true })`), so they work while the swap key is still held. Digits 1 to 9 pick the item at that number in the arm you are on; every tile shows its number. `useFit` remeasures on resize, through a ResizeObserver and on timers after mount, because the menu mounts while the window is still pet-sized.
- **Alt+arrow and Alt+digit while the Plus menu is open are global shortcuts.** The swap key's modifiers plus Up, Down, Left, Right or 0 to 9 are registered as the menu opens and released as it closes, so Alt+T and Alt+Left (or Alt+1) in the same breath land before the window has the keyboard. They arrive as `arm-*` and `pick-*` commands; `plus/arms.ts` is the one path that points at an arm or a number, and a point made before the menu mounts waits as a hint. In the menu, 0 is always the couch: a tile at the end of the ledger arm that turns the entry arm into the couch list.
- **A swap does not reset the block clock** except in blitz, where the timer belongs to the entry. A swap you ask for (the Plus menu, Alt+Q) also resumes a desk on hold or waiting, so switching tasks is one act; a swap the desk makes on its own, such as the next entry after a clear, leaves a hold alone.
- **The Plus menu previews choices until it closes.** Ledger, entry, mode and couch picks stay in temporary UI state. `App` sends the final `desk/select` once on every exit path, and the reducer applies it against the current desk. Browsing never changes swap history or resumes a held timer; opening and closing without a pick does nothing. Orders close the menu before taking effect.
- **Superset slots with nothing open still run**, as ledger time.
- **Tasks and the couch share one clock.** Picking a couch item while a task's block runs (or a task while on the couch) goes through `swapAcross` in the reducer: the block changes kind and what it is on where it stands, and the time already run stays. A pomodoro flips to `couch` and back, so the block after the rest is the same kind of thing; a superset keeps its round and slot and goes on to its next slot. Blitz times the entry itself, so it deploys the couch apart. `desk.previous` can hold a `leisureId`, so Alt+Q toggles across. The couch's coins come from its own time, not the block's, as below. During a rest, or from idle, picking the couch still deploys it apart, as below.
- **Deploying a different task parks the running session.** The desk holds one parked session in `desk.holster`, with its own sitting and the time already spent on its block. Picking the current task keeps its clock; picking a parked task resumes that session. `desk/switch` (Alt+Q) swaps the two; a stand down brings the parked one back paused. Nothing is minted while parked.
- **A rest is never a quick-switch target.** Before advancing into rest, `advanceDesk` saves its task and plan position in `desk.restTask`. Parking or switching resolves the rest to that task with a fresh block, keeping the completed focus count and the next leisure charge id. During rest, swap-back still prefers the previous real task. Old saves resolve a parked rest from the sitting's segments. Automatic rest cadence is unchanged.
- **Alt+Q opens a task switcher, Alt+Tab style.** The shell only sends `switcher`; App owns the choice, because a tap can end before the list mounts. Letting go of the hotkey's modifier commits. A mouse move with the modifier up also commits, since a release before the window had the keyboard is never seen. What is highlighted is what you get (`switcherAction` in `selectors.ts`): a row that is the swap-back goes through `desk/switch` so its clock returns, any other row is `desk/select`, and only ledger time, which the list cannot show, takes the plain switch from the first row. The list opens mid-screen under a resting pointer, so the pointer steers only after it has moved `SWITCHER_STEER_PX` from where it was first seen.
- **Alt+Q is a two-place toggle, and a swap-back beats the parked session.** Every swap writes the entry it left into `desk.previous`; the switch swaps back to it inside the same sitting, like a primary and a secondary weapon, and only falls back to the holster when there is no such entry. A swap to a third entry drops the oldest, parked or not; a cleared entry on the other side gives way to its ledger. The parked session still returns on a stand down.
- **A desk found running at launch is paused at the last heartbeat.** Time the app could not see is not desk time. Not on the phone: a phone is locked through most of every block and the person means it to run, so `src/phone/engine.ts` never pauses on its own; the tick replays each block end when it comes back, and `notify.ts` scheduled a notification for each.

A `done` line from 0.1.69's answer hooks is refused by `eventOf`. The desktop apps (Claude, ChatGPT with Codex, Gemini) and the browsers have no hooks, so on Windows `agents.ts` also runs `ai-watch.ps1` (copied to `~/.mayorly` at launch, one hidden PowerShell, gone with Mayorly): it reads only the app in front through UI Automation, looks a few containers up from the focused element for a Stop button (`Stop`, `Stop response`, `Stop generating` and the like), and writes a prompt when one appears (`claude-app`, `chatgpt-app`, `gemini-app`, `*-web` by the window title, `browser` for a side panel), but only where the app was in front and idle for 2.5 s just before (`Step-Prompt`: an app brought back while it still answers shows its Stop button already there, and an answer that thinks in steps hides and shows it between them; `-Test -Report file` runs the rule on made-up timelines). The extension's `CONTENT` keeps the same rule, and `onInstalled` puts it into open ChatGPT and Gemini tabs. The Codex app is not read on the screen at all (its hook hears every prompt you type, and an agent run there stops and starts by itself); the Claude app's Stop button waits `PAIR_WAIT_MS` and gives way to Claude Code's hook when it spoke within `PAIR_MS` (`pairedHook` in `aiswitch.ts`), so a session restarted by a background task or a schedule never switches, and plain Claude chat, which has no hook, still does. Chromium apps expose their contents only while visible, which the app in front is. `-Once -Report file` prints what it sees. ChatGPT and Gemini in Chrome also have the unpacked extension in `~/.mayorly/chrome-extension` (also written at launch) watches for the page's Stop button, whose appearing is the prompt, and posts to 127.0.0.1:47731 with the token in `~/.mayorly/token`; nothing without the token is heard. The rule is `settings.autoSwitch.aiPrompt` (a device setting; the earlier `aiBreak`, `autoSwitch.claude` and `claudeSwitch` carry over). The page's hit test turns that off as soon as it hears the pointer, through Electron's forwarded moves, but those ride a low-level mouse hook that Windows starves while a program running as administrator is in front (a game with anti-cheat) and drops for good when the app once answers it late, and a Mayorly running for hours still stopped taking the tomato. So `pollCursorWin` in `overlay.ts` samples the cursor (every 40 ms near the pet, 100 ms elsewhere) and decides too: arriving over the pet's box (`onPet`: `nearPet`, or the open drawer's box) takes the pointer and re-pins the window on top; going more than `PET_NEAR_PX` off lets it go, whatever the page last said; each call is told to the page (`onHit`), so its exact hit test carries on from there. While the tomato is carried (`setHeld`) nothing changes. It never sends a made-up mouse move: one says no button is down, which ends a drag in `Pet.tsx` the moment it starts. If the pointer moves on the pet with the window taking it and the page hears nothing for `DEAF_MS` (Electron's `input-event`), the log says `[overlay] deaf` with what the shell believes. Global hotkeys cannot reach the app while such a game has focus; that is Windows and the game, not something the app can register around.

- **Every push to `main` that touches the app is a release** (`dist.yml`, version `0.1.<run number>`). The app downloads it quietly and asks Update now or Later once per version, never over a running focus block and never while a panel is open (`offerUpdate` in `index.ts`). On a Mac that prompt and the file dialogs are app-modal while the overlay floats at screen-saver level, so `underMacDialog` makes the overlay yield (`overlay.yieldTo`) until they are answered; a dialog under an open deck froze both. A Mac without a Developer ID signature (every build until the certificate exists, `ship:mac` included) updates itself in `src/main/macupdate.ts`: the release carries the ad-hoc feed as `mayorly-mac.yml` with the commit, the app downloads the zip, checks the sha512, that it is `app.mayorly` and that its signature holds, and a detached script swaps the bundle once the app has quit (`logs/update.log`). A release from the commit the Mac already runs, or published before its build, is never offered, so a `ship:mac` ahead of CI is not undone. Later installs on the next launch, not on quit, because `ship:mac` quits the app too. **The updater is otherwise silent.** Errors go to the log. Buying in the deck is a held press (`HOLD_MS`) or Enter on the selected card; the coins fly from the counter to the Buy button (`noteOrigin`). - **AI keys sync with the account, no passphrase.** `shared/ai/keysync.ts` and `vault.ts`: each device seals its keys (AES-256-GCM) under the vault's key and names each with an HMAC of the key; `/vault/items` upserts by that name, so the same key on two devices is one key, distinct keys all stay, and a removal remembered in ai.bin beats an add made before it. The vault's key itself is held by the server (`/vault/escrow`, sealed under an HKDF of `ESCROW_SECRET` or `JWT_SECRET`): the first device with the key hands it over once, any device that signs in takes it, and a device with no vault to join makes one with a random key. So nobody types a passphrase, at the cost of the end-to-end promise: whoever runs the server could open the AI keys. An old passphrase still unlocks a vault no device has handed over (`unlock`, behind "Use my old sync passphrase"). A key that arrives is checked again on this device (`checking`); the preferred model and provider are per device. Any number of keys per provider; a failing one hands the next call to the next. The bar is `minConfidence`, or with null the level tuned by trial: `AiClerk.calibrate` files the 24 lines in `shared/ai/tuning.ts` against four sample ledgers, scores levels from 50 to 95% by F0.5 (a wrong ledger counts worse than a missed one), keeps the result per provider and model in ai.bin, and writes every trial to the log as `[clerk]`. The trial goes one line at a time, `pace.gapMs` apart, so a free tier's per-minute limit is not met; a refused line waits, heals the key and is tried once more. Gemini answers a per-minute limit with the same "exceeded your current quota" as an empty account, and `ask` marks a key failing on it. - **Sync is last writer wins on the server, and never loses work on the client.** A server document enters this machine through `sync/replace` (taken whole, when nothing changed here since the last sync) or `sync/merge` (unioned with this machine's work otherwise; `src/core/merge.ts`); both keep this machine's own settings (`DEVICE_SETTINGS`), and the desk follows the active device (below). `sync.json` beside the save holds the revision, the time and the hash of the last match. - **One active device per account, and only it runs the desk.** `desk.device` is the computer a person used last and when; every user action claims it first (`engine.act` sends `desk/claim` ahead of the action, in the same step), while ticks, replans, sync, the clerk's filing and the sleep, lock and launch pauses go through `engine.dispatch` and claim nothing. Sync keeps the desk claimed later (`deskWinner` in `merge.ts`). On a tie, on the active device itself, its own desk always wins (`ctx.device` is passed in): the clock advancing claims nothing, so the server's copy with the same claim is only an older push of this desk, and taking it wound a finished rest back to the start. Elsewhere on a tie the active device's own copy beats one another computer holds. A computer that receives a desk running elsewhere holds it where it stands as it arrives (`heldAt`), and runs, mints and rings nothing; the pet says where it is running. Anything a person does there takes it over, and the clock carries on from the hold as if it never stopped, never past the end of the block. The computer that lost it closes its run at the moment of the takeover. The run the kept desk is timing is never overwritten by another copy; otherwise intervals merge with the later end winning. The device id is `device.json` beside the save; the name is the host name. A hold is a view of the owner's run, not a record: its interval end never beats the owner's, focus totals are always re-summed from the intervals (`focusFromLog`), and `syncContent` leaves the held desk out, so holding writes nothing. A push goes only when this computer has something the server lacks; plan-only changes go from the active device, at most every 15 minutes, for the calendar feed.
